# Google の正式アプリにする（Play ストア）

いまの配布は APK を渡して入れる方法です。この資料は、**Google Play に載せて公式アプリにする**ときの手順です。いますぐ出す前提ではありません。出すと決めたら、この順で進めます。

Play に出すと、知らない人も入れられるようになります。少人数のままにするなら、内部テストまたはクローズドテストだけで止めても構いません。

公式の窓口:

- [Play Console](https://play.google.com/console)
- [アプリを公開する（Play Console ヘルプ）](https://support.google.com/googleplay/android-developer/answer/9859152)
- [新しい個人アカウントのテスト要件](https://support.google.com/googleplay/android-developer/answer/14151465)
- [Flutter の Android 配布](https://docs.flutter.dev/deployment/android)

## いまの状態と、ストア用に足りないもの

| 項目 | いま | ストアに出すとき |
| --- | --- | --- |
| 入れ方 | APK をファイルで渡す | Play から入れる |
| 提出ファイル | `flutter build apk`（APK） | `flutter build appbundle`（AAB）。新規アプリは APK 不可 |
| 署名 | 開発用の debug 鍵 | 自分で作るアップロード鍵。Git に置かない |
| パッケージ名 | `com.geardoctor.gear_doctor` | 変えない。一度出したら変更できない |
| 表示名 | GearDoctor | ストアでも同じでよい |
| バージョン | `pubspec.yaml` の `1.0.0+1`。APK は `./scripts/build_apk.sh` で 0.0.1 ずつ上がる | 出すたびに `+` の後ろ（versionCode）を増やす |
| プライバシーポリシー | [`docs/privacy-policy.html`](privacy-policy.html) | 公開 URL が必要。GitHub Pages で出す |
| Strava 連携 | `127.0.0.1` への戻り。戻らないときは貼り付け | 審査で実機確認される。カスタム URL スキームがまだなら先に直す |
| Strava のアイコン | 使っていない | 公式ロゴは使わない（著作権） |

すでに debug 署名の APK を入れている端末は、ストア版を入れる前に一度アンインストールします。署名が違うと上書きできません。

## 出す前に決めること

1. **誰に見せるか**  
   内部テスト（自分と少人数）、クローズドテスト（招待した人だけ）、本番（ストアで誰でも）。新しい個人アカウントは、本番の前にクローズドテストが必須です。
2. **プライバシーポリシーの置き場**  
   本文は [`docs/privacy-policy.html`](privacy-policy.html) です。Play には GitHub の `blob` ページではなく、次の公開 URL を書きます。

   `https://hwengjp.github.io/GearDoctor/privacy-policy.html`

   この URL は、[Pages の設定](https://github.com/hwengjp/GearDoctor/settings/pages) で Source を Deploy from a branch、Branch を `main`、folder を `/docs` にすると開きます。日本向けなら本文は日本語のままでよいです。配信国を広げるときは、同じページに英語を足します。
3. **審査で通る連携**  
   審査担当が「連携する」を押して、ブラウザからアプリに戻れる必要があります。いまの貼り付け手順だけでは落ちることがあります。

## 手順

### 1. 開発者アカウントを作る

1. Google アカウントで [Play Console](https://play.google.com/console) に入る
2. 開発者登録をする。個人なら登録料は一度きり（2026 年時点で 25 米ドル）
3. 本人確認（身分証など）を出す。完了するまでアプリは出せません
4. デベロッパー名を決める。ストアに出る名前です

組織アカウントにすると、クローズドテストの人数要件が違うことがあります。個人なら次の「12 人・14 日」が付きます。

### 2. アップロード用の署名鍵を作る

debug 鍵のままでは出せません。リポジトリのフォルダで、一度だけ作ります。

```
keytool -genkey -v \
  -keystore ~/geardoctor-upload.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias upload
```

聞かれた名前や組織は、ストアの開発者情報と矛盾しないものでよいです。できた `.jks` とパスワードは Git に入れません。バックアップを別の場所に残します。鍵をなくすと、同じパッケージ名で更新できません。

リポジトリ直下に `android/key.properties` を作ります（`.gitignore` 済み）。

```
storePassword=<キーストアのパスワード>
keyPassword=<鍵のパスワード>
keyAlias=upload
storeFile=/home/<Linuxのユーザー名>/geardoctor-upload.jks
```

`android/app/build.gradle.kts` の release 署名を、debug からこの鍵に切り替えます。切り替え方の詳細は [Flutter の Android 配布](https://docs.flutter.dev/deployment/android) です。

### 3. AAB を作る

```
flutter test
flutter build appbundle
```

できたファイルは `build/app/outputs/bundle/release/app-release.aab` です。APK ではありません。

`pubspec.yaml` の版は、出すたびに上げます。APK は `./scripts/build_apk.sh` が 0.0.1 ずつ上げます。例: `1.0.0+1` の次は `1.0.1+2`。`+` の後ろは毎回大きくします。

### 4. Play Console にアプリを作る

1. すべてのアプリ → アプリを作成
2. 名前は `GearDoctor`
3. アプリ / ゲームは「アプリ」
4. 無料（販売しない）
5. 宣言（子ども向けではない、など）に答える

パッケージ名は AAB を上げたときに確定します。`com.geardoctor.gear_doctor` のままにします。

### 5. ストアの掲載情報

Play Console の「メインのストアの掲載情報」です。

| 項目 | 入れるもの |
| --- | --- |
| 短い説明 | 80 文字以内。例: 自転車部品の交換時期を、走行距離から知らせる |
| 詳細説明 | 何をするアプリか。Strava から走行を取ることを書く |
| アプリ アイコン | 512×512 PNG。いまのランチャー（WheelTool 由来のホイール）を拡大してよい |
| フィーチャーグラフィック | 1024×500 |
| スマートフォンのスクリーンショット | 2 枚以上。ホーム、同期、部品の詳細など |
| カテゴリ | スポーツ、または健康とフィットネス |
| 連絡先メール | 審査と利用者から見える |

Strava の公式アイコンや「Connect with Strava」画像は使いません。

### 6. アプリの内容（宣言）

Play Console の「アプリのコンテンツ」を埋めます。GearDoctor ではだいたい次です。

| 項目 | 目安 |
| --- | --- |
| プライバシーポリシー | 公開 URL。必須 |
| データのセーフティ | 端末内に残すもの（交換記録、走行、Strava のトークン）と、Strava へ送るものを申告する。サーバーには置かない |
| 権限 | インターネット。位置情報は取らない |
| 広告 | なし |
| アプリのアクセス | ログインは Strava の認可。Google アカウントログインはない |
| 対象年齢 | 質問に答えるとレーティングが付く。自転車メンテなら成人向けでよい |
| ニュース / 政府 / 金融 | 該当しない |

データのセーフティでは、曖昧に「取らない」と書かないでください。Strava の Client Secret とトークンは端末の SQLite に残ります。審査で実機を見ます。

プライバシーポリシーの本文は [`docs/privacy-policy.html`](privacy-policy.html) です。Play Console には GitHub Pages の URL を貼ります。内容を変えたら、この HTML を直してから出し直します。

### 7. 内部テスト（自分で確認）

少人数の確認は、内部テストトラックが向いています。

1. テストとリリース → 内部テスト
2. AAB を上げる（Play アプリ署名を有効にする）
3. テスターに自分の Google アカウントを入れる
4. オプトイン用のリンクを開き、Play から入れる

ここで Strava 連携、同期、部品の表示まで通します。内部テストだけでは、新しい個人アカウントの本番は開きません。

### 8. クローズドテスト（本番の前）

2023-11-13 以降に作った**個人**の開発者アカウントでは、本番の前に次が必要です。

- クローズドテストを走らせる
- **12 人以上**がテストに参加している
- その 12 人が、申請直前まで **14 日連続**で参加したまま

人数が足りない、途中で抜けた、だとカウントされません。仲間が 12 人いないときは、本番を急がずクローズドのまま使う選択もあります。

1. テストとリリース → クローズドテスト
2. AAB を上げる
3. テスターのメールまたは Google グループを登録する
4. 参加用リンクを送り、各自が「参加する」を押す
5. 14 日待つ
6. ダッシュボードから本番へのアクセスを申請する（質問に答える）

質問では、誰に試してもらったか、どんな不具合を直したか、本番で誰向けかを書きます。少人数の自転車メンテなら、そのとおり書いてよいです。

組織アカウントで D-U-N-S などが通っている場合は、この人数要件が付かないことがあります。Play Console の表示に従います。

### 9. 本番に出す

本番アクセスが開いたら、

1. テストとリリース → 本番
2. 同じ AAB（または新しい版）を上げる
3. 国を選ぶ
4. 審査に出す

審査は数日かかることが多いです。落ちたら指摘を直して出し直します。よくある落ち方は、プライバシーポリシーの不足、データのセーフティの食い違い、連携が審査端末で完了しない、です。

公開後の更新は、`pubspec.yaml` の版を上げて AAB を作り、本番トラックに上げます。

## GearDoctor で先に直しておくこと

ストア審査の前に、次を済ませます。APK 配布のままでも直した方がよいものもあります。

1. **release 署名を debug からアップロード鍵へ変える**
2. **Strava の戻りを Android のカスタム URL スキームにする**（審査担当が貼り付けなしで戻れるようにする）
3. **GitHub Pages を有効にして、プライバシーポリシーの URL を公開する**（本文はリポジトリに済み）
4. **ストア用のスクリーンショットと 512 アイコンを用意する**
5. Client Secret を画面に入れる方式は、少人数なら審査で説明できます。不特定多数に出すなら、本来はサーバー側に置くべきものです。ストア公開と同時に利用者を広げるなら、先に方針を決めます

## 料金と期間の目安

| 項目 | 目安 |
| --- | --- |
| 開発者登録 | 一度きり（2026 年時点 25 米ドル） |
| 本人確認 | 数日 |
| 内部テスト | アカウントができてからすぐ |
| クローズドテスト（個人・新規） | 12 人が揃ってから最短 14 日 |
| 本番の審査 | 数日〜1 週間程度。差し戻しがあると延びる |

年額の Apple 開発者登録は、この手順には不要です。

## APK 配布との関係

Play に出したあとも、自分用の APK は作れます。署名はストア用のアップロード鍵（または Play が管理するアプリ署名鍵で再署名されたもの）と揃えないと、同じ端末で共存・上書きできません。

仲間だけに渡す当面の方法は、これまでどおり [開発と配布](開発と配布.md) の APK です。
